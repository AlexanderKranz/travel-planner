## Findings that change the plan
1. **Overpass is slow and unreliable from here.** Same day, public instance: 37 s for `node(1)`, 52-66 s for small `around` queries, one 502 ("too busy"), one query that **timed out and still returned HTTP 200 with empty `elements` and a `remark: "runtime error: Query timed out"`**. A 200 with an empty list must therefore not be cached as "empty": `parseElements` throws on a runtime-error remark. A kumi/private.coffee mirror call hung for 90 s. Consequences: client timeout is 45 s (spec said 30 s), page loads must not wait for more than one or two queries. `getPlacesFacts` has a 40 s budget for starting new queries on a page view (remaining groups become `status: "error"`); `warmTripFacts` runs without budget in `after()`. With a 30-day TTL this is acceptable, but the first view of a new place will often show "places unavailable" until the warm-up finished. `maxDuration = 60` on the trip page is required; consider a higher value on Vercel Pro. Plain `curl` without a User-Agent gets HTTP 406 from the Overpass status page: always send our UA.
2. **REST Countries v3.1 is deprecated** (HTTP 301 to a legacy file host, then `{"success":false,"errors":[{"message":"This API version has been deprecated ... migrate to v5"}]}`). v5 needs an API key (Bearer). Deviation: `scripts/countries/build.mjs` builds `src/data/countries.json` from **mledoze/countries** (the open dataset REST Countries v3 was built from; ODbL 1.0, 250 entries, 54 KB). That dataset has **no `car` (driving side) and no `timezones`**: driving side comes from a hand-maintained left-hand-traffic list in the script (Wikipedia list, re-check on rebuild), and `CountryFacts.timezone.countryZones` is always `[]` (the IANA zone and `Intl` offsets from the destination are unaffected). `SourceId` stays `rest_countries` (contract), but the attribution must name mledoze/countries (ODbL); `SOURCES.rest_countries` already points to it. Alex may prefer a free v5 key later; the output shape of the build script would stay the same.
3. **`christmas_markets` -> `none` [D12 applied].** `["xmas:feature"="market"]` within 15 km of Passau returned 0 elements (query succeeded, empty). Wien was not checked (each Overpass call costs ~1 min and the instance was overloaded). Impact: Danube-cruise demo shows "no verified source" for that interest, which is the documented fallback.
4. **Golf data quality (Marbella 40 km, 63 named elements):** contains driving ranges, "Par 3 Course", "Course A/B", a clubhouse node and a lessons node next to real clubs; only 1 element carries `wikidata`. Ranking by distance gives the top 25 including some noise. Not filtered in code (no deterministic rule); the AI step in phase 3 can pick, the UI shows OSM names as-is.
5. **Passau sightseeing (15 km):** 23 named elements, Dom St. Stephan, Veste Oberhaus/Niederhaus, Severinstor, Mariensaeule present with wikidata; a few non-sights ("Kubin Haus", a seminar centre in Schloss Neuburg) slip through `building`/`historic` tags.
6. suncalc 2.x ships its own types and returns `null` (not Invalid Date) for polar events; `@types/suncalc` is therefore **not** installed (it would conflict).

## Deviations from the spec (all small)
- `getPlaceById(id, lang)` / `searchPlaces(q, lang, ctx?)` call `cached()` themselves (backend-dev's contract); `getPlaceById` returns `null` for unknown ids and throws on provider errors. The "not found" answer is cached too (365 d).
- Wikivoyage "not found" uses the same 30 d TTL as hits (`cached()` takes one TTL per call; the 7 d rule would need a signature change).
- Overpass timeout 45 s instead of 30 s; `getPlacesFacts` takes an optional 4th argument `{ budgetMs }` (default 40 s). Signature stays compatible with the stub.
- `listCountries()` (code + English name) added to `src/lib/integrations/countries.ts` for the free-text country select.
- Interest cap: at most 4 interests with an OSM source; `none` interests are always reported as `no_source` and do not count.
- Climate cache key is `climate:v1:from=2016;lat=..;lon=..;to=2025` (endpoint name `climate`, provider `open_meteo_archive`).

## Quota and cost
- Open-Meteo archive: 105 weighted units per new location per year (one call). Geocoding: one call per distinct search string per 30 d, one per saved geo id per year (and the search results do not prime the `get` key: not implemented, a later optimization). All well below the free limits for a family-sized user base.
- Overpass: one query per (interest, place, radius) per 30 d, strictly sequential per request; no key, no cost, but availability is the risk (see finding 1). Set `OVERPASS_URL` to a self-chosen mirror if Vercel IPs get throttled.
- Wikivoyage: one call per (geo id, language) per 30 d.
- Open-Meteo free tier is non-commercial (ADR 0002).
